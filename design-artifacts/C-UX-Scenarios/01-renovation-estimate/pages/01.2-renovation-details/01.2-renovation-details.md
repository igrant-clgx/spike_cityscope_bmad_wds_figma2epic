## Overview

**Page Purpose:** Collect the renovation choices required to calculate an indicative cost range.

**User Situation:** The user has selected a valid property and needs to describe the renovation.

**Success Criteria:** Required answers are complete, an estimate request succeeds, and the result page receives the property and answer context.

**Entry Points:**

- Valid address selection from Address Search.
- Edit Estimate or New Estimate from Estimate Result.

**Exit Points:**

- Successful calculation -> Estimate Result.
- Enter new address -> Address Search.

**SEO:** `noindex, nofollow`; this is a transactional form route.

#### Accordion Semantics

- Each heading contains a native button with `aria-expanded` and `aria-controls`.
- Locked steps are disabled and expose the unmet prerequisite in accessible helper text.
- Only the current step is expanded by default; completed steps can be reopened without losing answers.
- Selecting a different Step 1 value clears only downstream answers that are no longer valid.
- Auto-opening the next step moves focus to its heading, not directly into the first control.

#### Button States

Default, hover, pressed, focus-visible, selected, and disabled use semantic state tokens. Selected state must include more than color alone.

## Validation and Errors

| Field / Group | Rule | Timing | Code | English |
|---------------|------|--------|------|---------|
| Renovation type | Internal is required for the fixed estimate path | After choosing External | `NOTICE_EXTERNAL_UNAVAILABLE` | This visual prototype supports the Internal Kitchen example only. Choose Internal to continue. |
| Renovation item | Kitchen must be selected before Step 3 | Locked-step helper | `PREREQ_KITCHEN` | Choose Kitchen to continue. |
| Fixed confirmation | Current state must contain property + Internal + Kitchen | Before estimate creation | `ERR_FIXED_PATH_INCOMPLETE` | Return to the incomplete questionnaire step. |

The unsupported-path notice appears adjacent to Step 1. Locked-step prerequisites
are associated with their disabled headings through accessible helper text.

---

## Responsive and Accessibility Requirements

- Use a single column on mobile; retain a readable maximum content width on larger screens.
- Buttons have at least 44x44 touch targets and wrap without truncating labels.
- Accordion focus, expanded, completed, selected, locked, loading, and error states do not rely on color alone.
- Preserve answers when navigating backward or reopening a completed step.
- Announce step changes and calculation progress politely; errors use assertive announcement only when submission fails.
- Focus the first invalid step heading on failed submission.

---

## Technical Notes

- Route guard requires a valid selected-property identifier; missing state returns to Address Search without rendering stale data.
- The prototype uses reducer-owned deterministic state and no network request.
- Native disclosure and option controls are deliberate accessibility/Figma
  exceptions where Ensemble components do not expose the required contract.
- No expanded Step 2 or Step 3 content appears in the supplied Figma frame; the
  fixed Kitchen selection and confirmation are approved product-specific
  extensions for the TS-001 demonstration path.
