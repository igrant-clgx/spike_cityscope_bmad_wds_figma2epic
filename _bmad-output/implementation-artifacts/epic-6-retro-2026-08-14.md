## 2. What Went Well

- **The dev-auto loop adapted cleanly to verification work — exactly as Epic 5 Action Item #5 prescribed.** The spec → implement → review → finalize loop held, but "implement" became "produce a verified artifact + any small remediation" and the reviewer shifted from "find the injected bug" to "confirm the audit is complete, honest, and evidenced." One proportionate adversarial auditor per story (vs the two-parallel bug-hunt for code stories) spot-checked every citation, count, and measurement empirically. The process guidance written *in the prior retro* was executed without re-litigation — the methodology reasoning about itself, correctly.
- **The verification found the product already sound — because the guarantees were built in, not bolted on.** Across five audits: 0 screen-state gaps, 0 responsive-overflow defects, 0 PII leaks, 0 seam-composition defects. This is not luck — it is the compounding dividend of five epics of machine-enforced seams. 6.1 enumerated states against four already-tested view-state mappers; 6.4 audited a PII boundary that was *already* a passing arch test + compile-time `AssertNoPII` + runtime scan; 6.5's E2E journey composed stubs that already had unit coverage. The release-readiness epic mostly **cited existing enforcement** rather than discovering problems.
- **Honesty about the node-only ceiling became a first-class deliverable — not a hidden limitation.** Every artifact draws the line explicitly: rendered reflow, focus movement, SR-announcement timing, Web Vitals, and cross-browser rendering are **documented manual-passes**, and real at-rest encryption / rate-limiting / TLS config are OI-11 `deferred` / infra `manual-pass`. Zero test/build dependencies were added to fake dynamic automation. The adversarial auditors specifically checked for overclaim — nothing browser-dependent was smuggled in as an automated `pass`. The spike reports its own reach truthfully.
- **The one carried a11y class finally closed — with real code, not another defer.** The competing-live-region defect that recurred in *every* prior epic ended in 6.2: both persistent regions moved to `visuallyHidden` (SR-only, one per surface, empty at rest), node-tested via `clip:rect` + text-present assertions. The Story 4.4 focus-order item was specified as a concrete manual-pass remediation rather than shipped unverifiable. The dedicated a11y verification story was the right home, exactly as Epic 5 predicted.
- **OI-11 real-sink hardening was framed as a single isolated substitution — the seam thesis proven at the exit.** 6.4 wrote the real-backend requirements (bounded/TTL ledger, real encryption, enforced retention, real rate-limiter, TLS/CORS/API-key) as things the *existing* `LeadSink` / route seams already isolate — no spike rework implied, just a documented adapter swap. The architecture's central bet (swap the adapter, keep everything else) is validated not by another feature but by how cheaply the production gaps are described against it.
- **The E2E journey proved the whole pipeline assembles — the fidelity thesis made literally executable.** `journey.e2e.test.ts` walks address→estimate→lead through the concrete stub adapters via the real use-cases with nothing mocked, asserting ids thread across all three seams, idempotency dedups, the consent gate blocks, and no PII serializes into analytics. The auditor confirmed it is a genuine, non-vacuous journey. The spike's closing test *is* the pipeline running green end-to-end.

## 3. What Was Challenging

- **Verification honesty is a discipline, not a default — the minor findings were all precision failures.** Every one of the ~9 minor findings was an **overclaim of certainty**, not a wrong conclusion: 6.1's "compile-time-total" (the mappers are `if`-chains, not `assertNever` switches — completeness is test-enforced, not compiler-guaranteed); 6.5's "the taxonomy fires with no PII" (the events are hand-tracked in the test, proving the typed contract + serialization, not pipeline auto-emission); 6.4's "throws" vs `Promise.reject`. The audits were *correct* but occasionally claimed a stronger guarantee than the mechanism provides. The reviewer loop's real job in a verification epic is policing the exact strength of each claim — the gap between "verified" and "verified by X specific mechanism."
- **The node-only harness is a hard ceiling on release-readiness confidence — and pretending otherwise was the constant temptation.** A genuine release-readiness epic *wants* Lighthouse numbers, axe scans, real cross-browser runs, and rendered-reflow screenshots. The harness provides none. The right move — documenting these as manual-passes with concrete checklists — is less satisfying than a green automated assertion and required deliberate restraint on every story. The honest artifact says "here is the rule, here is what a human must still confirm in a browser," which is correct but visibly less complete than a production QA gate would be. This is the spike's one structural limit, now fully mapped rather than glossed.
- **"Small remediation" needed judgement to stay small.** 6.2's live-region fix and 6.5's E2E journey were real code in an epic nominally about audits — the risk was scope-creeping a verification story into a feature story. Both were kept tight (a `visuallyHidden` swap + 2 tests; one composed journey test + no production change) precisely because the specs pre-committed to "artifact + *any small* remediation." Without that framing, the temptation to "just also fix/refactor while auditing" would have blurred the epic's purpose.
- **Measuring the real bundle required going around the tooling.** This Next version's build summary prints no per-route size columns, so NFR-3's budget baseline had to be measured directly from `.next/static/chunks` via `gzip | wc -c`. A small friction, but a reminder that even "just measure it" verification can require working around the ecosystem's defaults — and that a measured number beats an assumed one.

## 7. Pipeline-Fidelity Verdict

The spike set out to answer one question — does design intent survive the pipeline from Figma through the BMAD/WDS agent methodology into implementable code without drift — and six epics in, the answer is an evidenced **yes, and it compounds.** Epic 6 was the closing argument, and it argued not by building but by *looking*: five systematic audits across screen-state, accessibility, responsiveness/performance, security/privacy/reliability/observability, and test/browser coverage, every one turning up **zero product defects** because the guarantees had been built into the seams epic by epic rather than inspected in at the end. The release-readiness epic mostly *cited* machine enforcement that already existed — a passing boundary arch test, compile-time and runtime PII guards, a consent gate ordered before dedup, four exhaustively-tested view-state mappers, five isolated adapters — which is the strongest possible evidence that fidelity held: the verification found nothing to fix because the pipeline had refused to let the drift accumulate. Where the epic showed strain it was, tellingly, in *its own honesty* — every minor finding a claim that overstated the *strength* of a real guarantee (test-enforced coverage described as compiler-total, a typed-contract test described as pipeline emission), and the reviewer loop's job became policing the exact reach of each assertion rather than hunting injected bugs. The node-only harness remains the one true ceiling, now fully mapped into concrete manual-pass checklists rather than pretended away, and the production gaps (real CRM, real encryption, real rate-limiter, real pricing) are described so cheaply against the existing seams that they read as scheduled substitutions, not open risks. The methodology reproduced its central seam a fifth time at near-zero cost, adapted its own review loop from bug-hunt to audit exactly as the prior retrospective instructed, and closed its last recurring defect class with real code. The spike is complete: the design survived, the architecture held, the reviewer loop caught what the gates could not, and the pipeline did not merely transmit intent faithfully — it hardened it at every stage into guarantees that the final epic could only confirm.
