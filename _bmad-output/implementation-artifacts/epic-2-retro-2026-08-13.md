## 1. Epic Summary

**Goal:** Deliver the address-entry surface — the entry point to the renovation-estimate journey. A homeowner sees their current property address (or an honest empty state), opens a focus-trapped autocomplete modal, searches and selects a prediction that resolves into a structured AU address, or falls back to manual entry when the service fails or returns nothing — all non-destructively — and changing an already-confirmed address resets dependent scope to a defined state. All behind an `AddressProvider` port (stub adapter) with a BFF boundary and TanStack Query async ownership.

**FRs covered:** FR-4, FR-5, FR-6, FR-7, FR-8, FR-9, FR-32, FR-33

UX-DR9/UX-DR16/UX-DR18/UX-DR20 (address slice): change control, four service states, focus-trap/return, announced field errors.

## 2. What Went Well

- **Epic 1 action items landed before they blocked us.** TanStack Query (Action 1) was configured *inside* Story 2.1, exactly when first needed; the interaction-testing decision (Action 2) was written into the Story 2.3 spec *before* implementation. Both critical prep items from the Epic 1 retro were resolved on schedule — the retrospective loop is demonstrably working.
- **The port/envelope seam held under real feature pressure.** The address service was built entirely behind `AddressProvider` + the AD-9 envelope. Suggest and resolve both re-validate input *and* output at the BFF; the UI never branches on data origin (autocomplete vs manual produce the same `ResolvedAddress`). This is the pipeline-fidelity thesis working: intent expressed as seams survived into code.
- **The two-parallel-reviewer loop earned its keep.** In Story 2.3 both reviewers independently converged on two HIGH stale-state defects (transient modal state surviving close and query-edit) that unit gates would not have caught. Codifying the loop (Epic 1 Action 5) paid off in exactly the class of bug it targets.
- **Non-destructive error UX was designed, not bolted on.** Story 2.4 read failures from the non-throwing `apiFetch` envelope (`ok === false`, not `isError`) and kept the user's typed query intact through retry and manual fallback — the four UX-DR16 states rendered as specified.
- **Forward-compatible domain modelling.** Story 2.5's `changeAddress = setAddress(emptyForm(), address)` resets *all* dependent scope by rebuilding from the baseline — so an Epic 3 scope slot added to `emptyForm()` is reset automatically with zero edits to the reset logic. Intent encoded structurally rather than enumerated.

## 3. What Was Challenging

- **Stale transient UI state was the recurring defect class.** Story 2.3's two HIGH findings were both "state that should have been reset wasn't." Node-only tests (no jsdom/RTL) cannot exercise open→close→reopen or type-edit interaction sequences, so this class is invisible to the automated suite and relies on the reviewer loop + manual a11y checks to catch. Recurred as the deferred low-severity item in Story 2.5.
- **The node-only test harness has a real, repeated coverage ceiling.** MUI `Dialog` renders its body through a Portal that `renderToStaticMarkup` (SSR, no DOM) does not emit — forcing the `AddressModalBody` extraction. Interaction-level behaviour (focus-trap/return, toast firing, first-set-vs-change wiring) is covered by *documented manual a11y checks*, not assertions. This is a deliberate, spike-calibrated trade-off, but it is now a standing gap noted three times.
- **An `[OPEN]` product decision had to be assumed to make progress.** OI-7 (does changing a confirmed address *clear* or *keep* dependent answers?) is unconfirmed. Story 2.5 shipped the documented `[ASSUMPTION]` (clear + notify) and flagged OI-7 for product confirmation. Correct for a spike, but it is unratified intent carried forward into Epic 3's build surface.
- **Schema evolution rippled across three synchronized artifacts.** Story 2.4 evolving `resolvedAddressSchema` (`geo` optional; `street`/`suburb` trimmed) required keeping the Zod schema, the plain-TS domain port mirror, and the type-drift guard in lockstep. Handled cleanly, but it is a manual three-point synchronization every time the shared shape changes.

## 8. Pipeline-Fidelity Observations (spike-specific)

- **Traceability held.** Every Epic 2 story spec carried its FR/AD/UX-DR/OI IDs verbatim into acceptance criteria and into the `## Auto Run Result` summaries. A reader can trace FR-9 → Story 2.5 spec → `changeAddress` → test, unbroken.
- **`[OPEN]` items are the fidelity stress point.** Where product intent was undefined (OI-7), the pipeline did not stall — it assumed, documented the assumption, and flagged for confirmation. This is the correct failure mode, but it means *unratified* intent is now encoded in code and must be reconciled, not just remembered.
- **The reviewer loop is where design intent gets defended.** The class of defect the automated (node-only) suite cannot see — stale interaction state — is exactly what the adversarial reviewers caught. For a pipeline that deliberately runs lean tests, the reviewer loop is load-bearing, not optional.
- **Seams absorbed change without UI churn.** Schema evolution (2.4) and the reset mechanism (2.5) landed behind ports/aggregates with no downstream branching — evidence the architecture spine is doing its job of localizing change.
