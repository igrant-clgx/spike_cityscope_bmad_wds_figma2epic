# Epic 6 Context: Release Readiness & Verification

## Goal

The spike's closing argument: prove the assembled product (Epics 1–5) is trustworthy and shippable through a **whole-system verification pass — not new feature build**. Per-surface states and accessibility were built story-by-story; Epic 6 confirms completeness and runs the checks that can only exist once the full system does — sign off the complete screen-state matrix (FR-35, UX-DR16), run the WCAG 2.1 AA accessibility **audit** across the whole app (NFR-1), verify responsive behaviour and performance across all breakpoints (NFR-2/NFR-3, UX-DR21), verify the security/privacy/reliability/observability invariants (NFR-5/6/7/8, verifying AD-9/AD-10/AD-12), and land the cross-journey test suites and browser-support matrix (NFR-11/NFR-12). Because this is a node-only test harness (no jsdom/RTL/browser, no axe, no E2E runner), each story's deliverable is a **verification artifact** (matrix / audit doc) plus any small remediation code where a real gap is found — not net-new features. Epic 6 also resolves `[OPEN]` OI-5 (state-matrix completeness source of truth) in Story 6.1, records `[NOTE]` OI-4 (mobile/tablet hi-fi mock gap) in Story 6.3, and frames the OI-11 real-`LeadSink` hardening in Story 6.4.

## Stories

- Story 6.1: Screen-state matrix sign-off
- Story 6.2: Accessibility audit (WCAG 2.1 AA)
- Story 6.3: Responsive & performance verification
- Story 6.4: Security, privacy, reliability & observability verification
- Story 6.5: Test suites & browser support matrix

## Requirements & Constraints

- **Screen-state completeness (FR-35, UX-DR16 sign-off):** every surface — address, form, results, lead — is confirmed to implement empty/initial, in-progress, validation-error, loading, success, API-error, and empty/low-confidence states. Any gap is logged as a defect against the owning epic, not silently patched. Story 6.1 resolves `[OPEN]` OI-5 by naming the single source of truth for matrix completeness (the discriminated view-state mappers and their exhaustive node tests).
- **Accessibility (NFR-1, UX-DR20):** automated axe checks pass with zero critical violations across all routes; full keyboard-only traversal succeeds with visible focus at every step; a screen-reader pass confirms step-change and result-arrival announcements plus correct labelling. This is the class the node-only harness cannot assert automatically — 6.2 is where the documented manual a11y pass becomes a first-class artifact and where all deferred SR-only items converge (see Cross-Story Dependencies).
- **Responsive & performance (NFR-2, NFR-3, UX-DR21 completion):** desktop/tablet/mobile layouts reflow correctly with the disclaimer persistent and no horizontal scroll; performance budgets are met per NFR-3. `[NOTE]` OI-4 (the mobile/tablet hi-fi mock gap) is recorded against any layout judgement calls made in the absence of high-fidelity mocks.
- **Security / privacy / reliability / observability (NFR-5, NFR-6, NFR-7, NFR-8, AD-10, AD-12):** no PII crosses the client-to-external boundary; lead data is consent-gated and marked for encryption at rest; rate-limiting/reliability behaviour is verified per NFR-7; the `AnalyticsSink` emits the defined events with no PII. Honesty constraint: **no rate-limiting exists in the spike today** — NFR-7 verification documents current reliability behaviour (non-throwing `apiFetch`, bounded retries, envelope error path) and specifies the rate-limit requirement against the BFF seam rather than asserting a control that isn't built.
- **Test suites & browser matrix (NFR-11, NFR-12):** unit, E2E (journey against stubs), and automated a11y suites "exist and pass"; the E2E journey runs green against the stub adapters end-to-end; the supported browser matrix is documented and verified. Harness ceiling: there is **no E2E runner (Playwright/Cypress are not installed)** and **no axe integration** — 6.5 must reconcile these ACs to what a node-only harness can actually run (see Technical Decisions / Verification Approach).

## Technical Decisions

- **Node-only test harness is the defining constraint.** Tests run under Vitest in Node with **no jsdom / RTL / browser**; component tests render with `renderToStaticMarkup` from `react-dom/server` (static HTML only — no events, focus, layout, or timing). Pure-logic functions are the primary coverage vehicle. `@mui/icons-material` is **not** installed. **Do not add test dependencies casually** — the Epic 5 retro explicitly warns against adding deps "to fake" in-browser assertions. This ceiling shapes what 6.2/6.3/6.5 can automate vs. must document.
- **Existing machine-enforced artifacts to audit (verify, don't rebuild):**
  - Boundary purity — `src/server/architecture.test.ts` guards the inward dependency rule (domain/adapters import no `next`/`react`/`@mui/*`/`zod`; no adapter imports another). This is the concrete artifact 6.4 audits for AD-9/layer integrity.
  - Design-token enforcement — `src/theme/no-adhoc-hex.test.ts` (+ `src/theme/theme.test.ts`, `tokens.ts`) rejects ad-hoc hex outside the token layer.
  - Analytics AD-12 guards — `src/server/domain/ports/analytics-sink.ts` carries the compile-time `AssertNoPII<T>` type check and the runtime `FORBIDDEN_PII_KEYS` list; the event taxonomy (`StepViewed/StepCompleted/DropOff/EstimateGenerated/LeadSubmitted`) is enforced no-PII. 6.4 verifies NFR-8/AD-12 against these guards.
  - Consent gate — `src/server/adapters/lead/stub-lead-sink.ts` rejects any consent-less capture (ordered before the idempotency ledger) and marks the record for encryption at rest. 6.4 re-verifies AD-10/NFR-6.
  - View-state mappers — `src/features/results/results-view-state.ts` (`toResultsView`) and `src/features/lead/lead-view-state.ts` (`toLeadView`), each with exhaustive node tests, are the enumeration basis for the 6.1 state matrix.
  - BFF routes — `app/api/v1/{address/suggest,address/resolve,config/form,estimate,leads,health}/route.ts` re-validate input and output against shared Zod schemas and return the AD-9 envelope; these are the client→external boundary 6.4 audits for PII.
- **Verification Approach (spike-adapted).** Epic 6 stories produce **verification artifacts (matrices / audit docs) + small remediation**, not net-new features. The dev-auto reviewer loop shifts from "find the injected bug" to **"confirm the audit is complete, honest, and its claims are evidenced"** — each 6.x story ships a verification artifact plus any small remediation where a real gap is found; do not force net-new code where a verified matrix/audit is the deliverable. Per-story ceiling:
  - **6.1 (matrix):** fully achievable in-harness — enumerate every surface × state directly from the discriminated view-state unions and their exhaustive tests; any missing arm is a real, test-visible defect. Resolve OI-5 by naming these mappers as the completeness source of truth.
  - **6.2 (a11y):** cannot run in-browser axe/keyboard/SR assertions. Automate what static markup allows (accessible names, roles, `aria-describedby` wiring, label association, live-region presence in `renderToStaticMarkup` output); everything dynamic (focus movement, SR announcement timing, keyboard traversal) becomes a **documented manual a11y pass** artifact, with small remediation for the carried live-region/focus items.
  - **6.3 (responsive/perf):** no browser, no layout engine, no Lighthouse. Verify via static analysis of breakpoint/`sx` usage and the disclaimer's persistent placement, plus a documented manual responsive check and build-output inspection; record OI-4 against any judgement made without hi-fi mocks. NFR-3 budgets are documented targets, not asserted numbers.
  - **6.4 (security/privacy/reliability/observability):** strongest in-harness story — the boundary arch test, `AssertNoPII`/`FORBIDDEN_PII_KEYS`, and the consent-gate test are already machine-enforced; 6.4 re-confirms them end-to-end and writes the OI-11 real-sink requirements (bounded/TTL dedup store, real at-rest encryption) as the isolated seam substitution. NFR-7 rate-limiting is specified against the seam, not asserted (no control exists yet).
  - **6.5 (suites/browser matrix):** unit + a11y-static + a **node-level journey test wiring the stub adapters through the application/BFF layer end-to-end** stand in for the browser E2E the ACs describe — honestly labelled as a node-harness E2E, not a Playwright/Cypress run. The browser matrix (NFR-12) is a **documented + reasoned** support matrix, since no cross-browser runner exists. Do not install Playwright/Cypress/axe to manufacture a green in-browser suite.
- **`noUncheckedIndexedAccess`** (tsconfig) remains a carried nice-to-have (deferred since Epic 1); enable opportunistically in a hardening pass if 6.x touches index-heavy code — not a blocker.

## UX & Interaction Patterns

- **State-matrix surfaces (UX-DR16):** the four surfaces to sign off are address, form (accordion stepper), results, and lead; the canonical state set per surface is empty/initial, in-progress, validation-error, loading, success, API-error, and empty/low-confidence. The `toResultsView`/`toLeadView` mappers already model discriminated view states; 6.1 confirms each surface's mapper covers the full set and logs gaps as owning-epic defects.
- **Accessibility semantics (UX-DR20):** fields programmatically labelled with `aria-describedby` errors, logical tab order, ≥44px targets, text-not-colour error signalling; the consent checkbox carries correct semantics; submission and result arrival announce via a persistent live region. 6.2's manual pass verifies the dynamic half of these (announcement + focus + traversal) that the node harness cannot assert.
- **Responsive persistence (UX-DR21):** the affordability disclaimer must remain persistent across desktop/tablet/mobile with no horizontal scroll at any breakpoint — the one non-negotiable responsive invariant 6.3 signs off (disclaimer copy lives in the results card and app shell).

## Cross-Story Dependencies

- Epic 6 is a **pure verification pass over Epics 1–5** — the full feature surface (address → scope → estimate → lead) is built and green, so every 6.x story audits existing, already-tested artifacts rather than building new ones. It requires no future epic.
- **6.2 is the single home for all deferred SR-only-correctness items** carried in `deferred-work.md` / the Epic 5 retro §6: competing `role="status"` live regions on the success screen (Story 5.4 → 6.2), post-action / lead-form focus management (Story 4.4 → 6.2), and lead-form state-change focus/announcement — each converges here for one documented manual a11y pass with small remediation (exactly-one-region-speaks; focus relocates sensibly after every transition).
- **6.4 frames the OI-11 real-`LeadSink` concerns** carried forward: the unbounded idempotency ledger in `stub-lead-sink.ts` (needs bounded/TTL eviction) and the encryption-at-rest stub marking (needs real at-rest encryption) are honest spike shortcuts written up as the isolated adapter substitution the seam already supports — not re-opened as spike work.
- **6.1 depends on** the discriminated view-state mappers and their exhaustive node tests (Epics 2–5) as the OI-5 completeness source of truth; **6.5 depends on** the stub adapters behind every port to run the node-level end-to-end journey green.
- `noUncheckedIndexedAccess` (carried since Epic 1) is the lone standing nice-to-have and gates nothing in Epic 6.
